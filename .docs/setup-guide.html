Steps

Setup, in order

Steps 1–8 can be done now. Steps 9–11 depend on later build phases or open decisions.

  1. 1

    Reload VS Code and approve the Power BI MCP server

    YouNow
    1. Close all VS Code windows, then reopen C:\__PBI\QBO. A plain window reload is not enough if PATH changed.
    2. When Claude Code asks about the project MCP server powerbi-modeling from .mcp.json, approve it.
    3. Type /mcp in Claude Code and check that powerbi-modeling shows as connected.

    The first model call may be refused until the Microsoft EULA is accepted. Claude will ask you; it accepts only on your explicit yes.

  2. 2

    Sign in to Azure and Fabric

    YouNow

    Run these in your own terminal. Both open a browser sign-in. Use the tenant that will host the Power BI workspace.

    PowerShell
    az login --tenant <tenant-id-or-domain>
fab auth login

# check who is signed in (prints no tokens)
az account show --query "{user:user.name, tenant:tenantId}" -o table
fab auth status

    "No subscriptions found" is normal for a tenant without an Azure subscription. Use az login --allow-no-subscriptions --tenant <tenant> and pick the tenant-level entry.

  3. 3

    Check Power BI Desktop and Service settings

    YouNow
    1. Desktop → File → Options → Preview features: turn on external tool access through secure local APIs, and the PBIP save option, TMDL and PBIR formats wherever they are still listed. Newer builds have some of them on by default.
    2. When the report exists, save it with File → Save as → Power BI project into PNL/. Claude only edits PBIP, never .pbix.
    3. Service: you need the Contributor, Member or Admin role on the workspace you will publish to.
    4. Only on Premium or Fabric capacity: the capacity admin sets the XMLA endpoint to Read Write if models will be edited in the Service.
  4. 4

    Verify the agent kit

    ClaudeAfter steps 1–3

    Paste this into Claude Code. It runs read-only checks: MCP server, skills, CLIs, sign-ins, validate.py. It asks before each smoke test.

    Prompt
    Run Phase 2 of pbi-fabric-agent-kit/SETUP.md.
  5. 5

    Start the Git repository

    YouNow

    The repository is git@github.com:rusloc/qbo.git. Claude never runs git in this project. The branch model is prod ← dev: all work is committed on dev and merged into prod regularly. There are no feature branches.

    bash
    # 1. check SSH access; expect "Hi rusloc! You've successfully authenticated"
ssh -T git@github.com

# 2. local repo and first commit
cd "C:/__PBI/QBO"
git init -b prod
git remote add origin "git@github.com:rusloc/qbo.git"
git add -A
git status   # expect: no .env, no pbi-fabric-agent-kit/, no *.zip, no *.pbix
git commit -m "chore: scaffold project and install pbi-fabric-agent-kit 2026-09-25"

# 3. what is already on GitHub? no output = empty repo
git ls-remote --heads origin

    If the GitHub repo is empty (step 3 printed nothing):

    bash
    git push -u origin prod     # first pushed branch becomes the GitHub default
git switch -c dev
git push -u origin dev

    If it already has commits (for example a README created on GitHub on branch main), merge them in first:

    bash
    git fetch origin
git merge "origin/main" --allow-unrelated-histories -m "chore: merge initial GitHub commit"
git push -u origin prod
git switch -c dev
git push -u origin dev

    Replace main with the branch name step 3 printed. If ssh -T fails, add your public key under GitHub → Settings → SSH and GPG keys. You can change the default branch later under the repo's Settings → General. CLAUDE-template.md is still at the project root and would go into the first commit; keep it or move it before you commit.

    Python 3.12, the virtual environment and dbt

    Done 2026-09-25YouClaude

  7. 7

    Create the Intuit developer app and sandbox company

    YouNow
    1. Sign in at developer.intuit.com, preferably with an account used only for development.
    2. Dashboard → create an app for QuickBooks Online. Select the Accounting scope only (com.intuit.quickbooks.accounting). Never add payments scopes (spec §1).
    3. Keys & credentials → Development: copy the Client ID and Client Secret into the .env file below.
    4. Redirect URIs: add the local callback that qbo_sync auth will listen on. It is fixed in Phase 1, for example http://localhost:8000/callback.
    5. Sandbox: open the sandbox company (US; spec asks for QBO Plus) and copy its Company ID. That is the REALM_ID.
    6. Use the API Explorer to look at entities. Fixture JSON goes into fixtures/ only after realm IDs are removed.
    etl/.env
    ENV=sandbox
CLIENT_ID=
CLIENT_SECRET=
REALM_ID=
DB_URL=

    Fill this file yourself. Claude is blocked from reading .env files, and .gitignore keeps them out of Git. Don't request production keys yet: build and test run against the sandbox only.

  8. 8

    Supabase: database logins and connection settings

    YouAfter migration M1

    The warehouse lives in the shared project vosk.dev, in its own schema qbo (ADR-0008, ADR-0003). This project doesn't use supabase link or supabase db push: the migration history of vosk.dev also holds another app's migrations. Claude applies each QBO migration through the Supabase MCP, and Claude Code asks you before every one.

    1. Once migration M1 has created the roles, enable their logins in the Supabase SQL editor. Keep both passwords in your password manager.
    SQL editor
    alter role qbo_etl    with login password '<from password manager>';
alter role qbo_reader with login password '<from password manager>';
    1. Dashboard → Connect → Session pooler: note the host. The user name is qbo_etl.<project-ref>, the port is 5432, and SSL is required. Add these lines to etl/.env: DB_URL is for qbo_sync, the other lines are for dbt.
    etl/.env (add)
    DB_URL=postgresql://qbo_etl.<project-ref>:<password>@<pooler-host>:5432/postgres?sslmode=require
QBO_DB_HOST=<pooler-host>
QBO_DB_PORT=5432
QBO_DB_USER=qbo_etl.<project-ref>
QBO_DB_NAME=postgres
DBT_ENV_SECRET_QBO_DB_PASSWORD=<password>
    1. Check dbt's connection. The second line loads etl/.env into this terminal session only.
    PowerShell
    cd C:\__PBI\QBO
Get-Content etl\.env | Where-Object { $_ -match '^[A-Za-z_][A-Za-z0-9_]*=' } | ForEach-Object { $k, $v = $_ -split '=', 2; Set-Item "env:$k" $v }
cd dbt
..\etl\.venv\Scripts\dbt.exe debug        # expect: All checks passed!

    Use the session pooler, not the direct host: the direct host is IPv6-only unless you buy the IPv4 add-on, and Windows networks are often IPv4-only. If the password contains @, : or /, URL-encode it inside DB_URL only.

  9. 9

    Connect Power BI Desktop to Supabase

    YouAfter the serve views exist
    1. Get data → PostgreSQL database. Server: <session-pooler-host>:5432. Database: postgres. Mode: Import.
    2. Credentials: Database, as qbo_reader.<project-ref>, the read-only role from ADR-0003. Don't store the postgres admin password in the report.
    3. Select the vw_* views in schema qbo only. Server and database become the parameters Server and Database, next to FY_START.

    If Desktop reports that the remote certificate is invalid, download the CA certificate from the Supabase dashboard (Database settings → SSL configuration). Import it under Trusted Root Certification Authorities for the current user (certmgr.msc), then connect again. How the Power BI Service refreshes (cloud connection or gateway) is decided in ADR-0006.

  11. 11

    Optional: pg-sqldev, a read-only catalog MCP for Claude

    YouClaudeAfter step 8

    Gives Claude table, column and index facts from Supabase without reading data rows. The source is in _mcp/pg-sqldev. The tests run offline:

    PowerShell
    cd C:\__PBI\QBO\_mcp\pg-sqldev
npm ci
npm test
    1. Create a dedicated read-only database role with usage and select grants on the warehouse schemas.
    2. Copy .env.example to .env in that folder and fill PGHOST (session pooler host), PGPORT=5432, PGDATABASE=postgres, PGUSER=<role>.<project-ref>, PGPASSWORD and PG_SCHEMAS.
    3. Run node scripts/probe.js once, then node test/smoke.js. When the smoke test passes, ask Claude to register the server in .mcp.json.

    Set PG_SCHEMAS explicitly: its default is the schema list of the project the kit came from. The README describes Azure Cosmos DB for PostgreSQL; the steps are the same on Supabase. After npm ci, validate.py reports third-party files under node_modules. That is a known kit issue.

A newly installed tool is "not found"Claude Code inherits PATH when VS Code starts. Close every VS Code window and reopen.
MCP server "failed" or "connection closed"In .mcp.json, command must be "cmd" with "/c" as the first arg. If /c became C:/, the server was registered through Git Bash; edit the file by hand.
